摘要

在计算生物学和 AI 制药领域，结构预测、分子生成、蛋白/多肽设计、分子对接、分子动力学以及 ADMET 评价已经形成丰富的算法与工具生态，但“工具很多”并不等于“科研流程已经自动化”。真实研究任务需要在不同程序、数据格式和计算环境之间反复切换。

BioBench 的目标，是把这些分散的生物计算能力重新组织成 Agent 可以理解、调用、组合和执行的 Skills。项目以 Agent 为任务入口，以 Skills 为能力单元，以 DGX Spark 的本地 AI 与计算资源为执行基础，以 Web Viewer 为结果呈现界面，形成“自然语言提出任务—Agent 拆解任务—Skill 执行计算—结果回到可视化工作台”的闭环。

一、我们真正想做的，不是再造一个工具

2026 年 9 月 21 日，我们开始进入 DGX Spark Agent Skills 开发挑战赛的实际开发阶段。最初提出了 AI 自动化设计和优化环肽药物、自动化视频生产两个方向，经过讨论最终确定“BioBench：一个生物工作台”。

我们的宏观叙事：把 AI 从“会回答问题”推进到“能够完成科研工作流”。

最终产品不是十几个按钮的工具集合，而是一个面向生物分子设计与分析的智能工作台。中央区域呈现蛋白质、配体和复合物三维结构；左侧提供结构指标、链信息和序列；右侧保留 Agent 对话区，使任务提出、计算过程和结果观察处于同一个界面。

二、核心架构：Agent → Skill → Scientific Engine → Viewer

用户提出任务后，Agent 理解并拆解任务，根 SKILL 负责路由与编排，Deploy Skill 准备环境，Run Skill 执行科学计算，结果写入统一工作区，Viewer 负责呈现。

User ↓ Agent / Harness ↓ BioBench 根 SKILL.md ├─ 任务理解 / 路由 / 编排 ├─ Deploy Skills：环境、模型、依赖、GPU、权重 └─ Run Skills ├─ 结构预测 ├─ 口袋检测 ├─ 分子生成 / 编辑 ├─ 蛋白 / 结合肽设计 ├─ 分子对接 ├─ 分子动力学 ├─ 序列设计 / 搜索 ├─ 结构比较 └─ ADMET 预测 ↓ Scientific Models / Tools ↓ Result Artifacts ↓ BioBench Viewer

这种设计避免 Agent 直接凭记忆操作复杂科研软件，而是通过结构化、可复用、可验证的 Skills 完成专业工作。

三、代码结构：把科研能力拆成可以组合的 Skill

Deploy Skills解决模型权重、Python、CUDA/PyTorch 和系统依赖的准备；Run Skills执行真正的科研动作；_shared统一路径、结构文件、环境匹配和错误处理；Viewer把计算结果重新变成蛋白结构、序列、指标等科研对象。

四、从一个想法到一个可以运行的工作台

  1. 方向确定：从 AI 环肽设计和自动化视频等方向出发，最终确定生物计算工作台。
  2. 建立 Skill 思维：将算法重新定义为 Agent 可以调用的能力单元，形成 Deploy、Run、Shared、Viewer 分层。
  3. 接入科学能力：逐步建立结构预测、分子生成、分子编辑、蛋白/结合肽设计、对接、动力学和 ADMET 等 Skills。
  4. 建立统一结果层：让不同计算任务产生的结构、状态和指标以统一方式发布。
  5. Agent 与 Viewer 联调：把自然语言入口、Skill 路由、科学计算和三维可视化连成闭环。

一个典型流程可以是：目标蛋白 → 结构预测/加载 → 口袋检测 → 分子或结合肽生成 → 分子编辑 → 对接 → 动力学 → ADMET。每个 Skill 可以独立存在，但真正的价值来自 Skills 之间的组合。

五、我们的创新：不是增加一个模型，而是改变模型使用工具的方式

  • 从工具集合变成能力网络：重点不是工具数量，而是能否被 Agent 组合。
  • 从“给答案”变成“执行任务”：Agent 可以把对接、动力学、生成等能力作为可执行 Skill。
  • 从单点算法变成科研工作流：多个计算阶段能够连续衔接。
  • 从命令行结果变成可视化科研对象：结果回到蛋白结构、序列、链和指标上下文。
  • 从一次性 Demo 变成可扩展框架：新增模型时可以优先增加 Deploy/Run Skill，而不必重做整个 Agent。
我们对 Agent Skills 的理解：不是给 Agent 增加一个“生物学知识库”，而是给 Agent 增加一套“做生物计算的手”。

六、为什么是 DGX Spark，以及下一步

BioBench 不能只停留在文本层。真实生物计算需要模型推理、结构计算、GPU 加速和大量中间结果处理。DGX Spark 作为本地 AI 与计算底座，使 Agent 更接近实际科学计算执行过程。

下一步，我们将继续提升复杂多步骤任务的自动规划、计算失败后的自动恢复、实验记录与结果追踪、多目标候选筛选，以及蛋白质工程、酶分子设计和 AI 制药模型的覆盖。

结语

传统计算生物学软件给研究者提供一把把工具；BioBench 想做的是把这些工具组织成一个真正能够工作的智能工作台。研究者先描述自己想解决的科学问题，Agent 再把科学问题拆解成可以执行的计算任务，并把每一步结果重新带回科研对象本身。

这就是我们对 Agent Skills 最直接的理解：让 Agent 不只是知道科学，更能够真正参与科学计算。
