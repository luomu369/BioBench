项目简介

做一次分子计算，经常要在几个工具之间搬文件：准备结构、选择参数、运行程序，再从日志里找结果。换一个任务，这些步骤又得重新来一遍。

BioBench 把常用工具接到一个工作台里。你可以查看三维结构，选中要处理的部分，再告诉 Agent 想做什么。Agent 根据对应的技能说明调用程序，查看器显示发布后的结构、指标和任务进度。具体计算仍由各个模型和软件完成。

一、适合用来做什么

目前的功能围绕生物分子结构展开，包括口袋检测、分子生成与编辑、对接、分子动力学、序列设计和结构比较。每项功能都有自己的运行环境和输入要求，使用前需要先完成相应部署。

界面中央是三维结构，左侧显示链、序列和结构信息，右侧是任务对话。比如想修改配体的一部分，可以先选中相关原子，再描述修改要求，不必在文字里反复解释原子的位置。

适合先用熟悉的结构做一个小任务，检查选区和输出是否正确，再尝试更长的计算流程。

二、任务由谁来执行

Agent 负责选择技能和组织步骤。技能文档说明适用场景、参数和检查方法，脚本负责调用计算工具。查看器读取发布文件，把结果显示出来。

用户：选中对象，提出任务 ↓ Agent：读取技能说明，选择执行步骤 ↓ 技能脚本：检查输入，调用模型或计算工具 ↓ 输出文件：结构、指标、日志和任务状态 ↓ 查看器：显示已发布的结果

分子计算工具在本机运行。当前默认配置通过云端模型接口完成 Agent 推理，因此使用前也需要配置模型服务。不同工具的依赖分开放在各自的环境中。

三、代码放在哪里

下面列出几个常用目录。部署技能和运行技能都直接放在 skills/ 下，每个技能通常包含说明文档和执行脚本。

BioBench/ ├── SKILL.md 项目入口与技能选择说明 ├── opencode.jsonc Agent 配置 ├── skills/ │ ├── boltzgen-deploy/ 模型部署 │ ├── molecular-docking/ 分子对接 │ ├── molecular-dynamics/ 分子动力学 │ ├── molecule-editing/ 选区编辑 │ ├── structure-viewer/ 结构与状态发布 │ ├── viewer-launch/ 环境检查与查看器启动 │ └── _shared/ 共用的路径、格式和检查函数 ├── webapp/ 查看器与服务端 ├── tests/ 自动化检查 └── vendor/ Agent 运行配置与安装脚本

接入一个新工具时，可以先写好技能说明和脚本，单独确认输入输出，再接到查看器。已有脚本也可以直接从命令行运行，便于排查问题。

四、一次任务怎么做

以修改配体后重新对接为例，可以分几步进行。下面是操作示意，实际参数和结果取决于输入结构与所用工具。

先看清楚要改哪里

打开结构，确认蛋白链、配体和残基编号。切换到原子选择模式，选中要修改的部分。如果选区不对，先调整选区，再发起任务。

把要求说具体

例如：“把选中的片段替换成苯环，保留复合物的其他部分。”选区会随问题一起交给 Agent，编辑脚本据此处理结构。修改后先检查连接位置和原子间是否重叠，再决定是否继续计算。

确认下一步的输入和参数

需要重新对接时，说明使用哪个受体和哪一个修改后的配体，并确认搜索区域、搜索强度等参数。运行较长的任务前，先核对 Agent 给出的执行方案；需要命令权限时，在面板中确认。

看结果，也看它是怎么算的

任务提交后，可以在页面查看进度。后台任务结束时，系统会尝试唤醒 Agent 读取结果并汇报。除了新结构和评分，还应检查运行日志、输入文件与实际参数。对接评分可用于比较候选，但不能直接当作实验结论。

也可以从更小的任务开始：查看一条链的序列，分析选中键的构象，或比较几个候选分子的理化性质。一次只改变一个条件，结果更容易核对。

五、使用中的几个细节

选区和问题一起传过去

选中的残基、原子或键会附在问题中。这样，“修改这里”有具体对象，Agent 不必先猜位置。存在歧义时，仍然需要确认到底处理哪一部分。

把参数和结果留在一起

发布结构时可以记录运行参数。再次对接或比较结果时，能从结构元数据里找到之前的设置，少翻几遍历史目录。是否完整记录，仍取决于对应技能的发布内容。

长任务有状态可查

面板会跟踪已登记的后台任务，结合进程编号和启动时间判断运行状态。任务不需要靠反复发送“跑完了吗”来推进；如果计算失败，仍要根据日志排查原因。

格式问题尽早发现

共用脚本检查结构文件格式、选区和部分原子重叠问题。已遇到的静默失败也记录在技能文档里，方便后续复查。这些检查覆盖的是已知问题，还不能保证所有输入都有效。

六、当前进展与待完善的地方

项目已经开源，基础服务加入了自动化测试。现有测试主要检查接口、输入处理和启动行为，不能代替具体分子计算的验证。

目前仍以单用户、单机使用为主。查看器默认只允许本机访问，远程使用建议通过 SSH 转发。多任务状态管理、失败后的恢复，以及不同机器上的部署还需要继续完善。

类药性相关功能目前提供理化描述符、规则筛选和结构警示，尚不能据此判断真实毒性或成药性。生成结构、对接和动力学结果也需要结合任务条件检查。

接下来会优先补充固定示例和计算回归测试，让输入、参数和输出更容易复查。如果使用时遇到问题，欢迎在仓库提交复现步骤、工具版本和已脱敏的日志；不要附上 API key 或不便公开的结构数据。
